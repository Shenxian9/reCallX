# RECALLX

RECALLX 是一个仅在本地工作的 Tampermonkey userscript，用于备份当前
X（`x.com` / `twitter.com`）页面中可见的用户主页、推文 URL，以及用户真实点击产生的
点赞、书签和关注记录。

它不调用 X 内部 API，也不会自动关注、点赞、收藏或滚动页面。当前版本的目标是提供一个
简单、可审查、无需构建步骤的 URL 备份工具。

## 当前 MVP 目标

- 在 X 页面右下角显示固定的 **RECALLX** 浮动面板。
- 保存当前用户主页或推文详情页。
- 扫描当前视口中已经渲染且可见的 `a[href]` 链接。
- 规范化 URL，并分别保存用户主页和推文记录。
- 使用 Tampermonkey 的本地存储按 URL 去重。
- 显示本地记录统计，并将完整数据导出为 JSON。
- 通过捕获阶段的点击事件委托，记录用户手动执行的点赞、书签和关注操作。

## 安装方式

1. 在浏览器中安装 Tampermonkey。
2. 打开 Tampermonkey 管理面板，选择“添加新脚本”。
3. 将 [`x-url-backup.user.js`](./x-url-backup.user.js) 的完整内容粘贴到编辑器。
4. 保存脚本，并确认脚本已启用。
5. 打开或刷新任意 `https://x.com/*` 或 `https://twitter.com/*` 页面。

项目不使用外部依赖和构建工具，userscript 文件可直接安装运行。

## 使用方式

页面右下角的 RECALLX 面板提供以下操作：

- **保存当前页**：当前 URL 为用户主页或推文详情页时，将其保存到本地。
- **扫描可见链接**：检查当前视口中可见的 `a[href]`，保存可识别的主页和推文 URL。
- **导出 JSON**：下载名为 `recallx-backup-YYYY-MM-DD.json` 的完整本地备份。
- **统计**：打开可视化统计窗口，按“URL 备份”和“交互记录”分类展示各集合数量、
  分类小计、记录总计、最后更新时间和数据版本。
- 用户在 X 页面手动点击红心、书签或关注按钮时，脚本会尝试识别附近的推文或用户主页，
  并分别备份到 likes、bookmarks 或 follows。

同一个规范化 URL 只保留一条记录。再次遇到已保存 URL 时不会重复新增。
所有 `savedAt` 和 `updatedAt` 时间均使用东八区（UTC+08:00）并带有明确时区偏移。

交互 URL 只保存在对应集合中，不会因为一次点赞同时在 `tweets` 和 `likes` 中保存两份。
`tweets` 和 `profiles` 仅用于“保存当前页”和“扫描可见链接”产生的普通 URL 备份。
用户取消点赞、取消收藏或取消关注时，RECALLX 会删除对应的 likes、bookmarks 或 follows
记录，但不会删除用户单独保存或扫描得到的 tweets/profiles 记录。

## 安全边界

- 不自动关注、点赞、收藏或执行其他账号操作。
- 只监听用户真实点击；脚本不会自动点击、恢复或重放任何操作。
- 不调用 X / Twitter 内部 API，不进行额外网络请求。
- 不执行无限滚动，也不主动加载更多页面内容。
- 不依赖 X 的 CSS class 名；只读取当前 URL 和页面可见的 `a[href]`。
- 所有数据默认仅通过 `GM_getValue` / `GM_setValue` 保存在本地。
- 不包含 GitHub 同步、云同步或自动上传。
- 不包含或硬编码 token、账号、密码等凭据。
- 行为识别只读取按钮的 `data-testid`、`aria-label`、文本及附近可见 DOM 链接，
  不依赖 X 的 CSS class 名。

## 后续计划

后续版本可以在保持用户明确控制和本地优先原则的前提下考虑：

- 本地备份导入与合并。
- 更丰富的筛选、搜索和本地数据管理。
- Markdown 等额外导出格式。
- 经用户显式配置后再提供可选的同步能力。

这些功能均不属于当前版本。
